# 架构基线：爱心静态网页

> 需求基线来源：`docs/wi-t1000514/requirements.md`（SHA-256 已校验）
> 应用类型：simple-frontend（精简路线）

## 1. 页面与交互范围

单个 HTML 文件，内联 CSS 与 JS，在浏览器中打开后直接渲染一个视觉上可识别的爱心图案。无用户交互、无表单、无导航、无数据读写——纯展示型静态页面。

覆盖验收场景 AC-01：浏览器打开页面文件后可见爱心图案。

## 2. 浏览器状态与数据归属

本页面不产生、不存储、不读取任何业务数据。无 localStorage、无 sessionStorage、无 Cookie、无 IndexedDB。页面状态完全由静态 HTML/CSS 决定，刷新或重新打开后结果不变。

## 3. 实现入口

- **文件**：`index.html`（项目根目录）
- **结构**：HTML 语义结构 + 内联 `<style>` 定义爱心图案样式 + 内联 `<script>`（如需绘制逻辑）
- **爱心图案实现**：使用 CSS 绘制（伪元素 + rotate 构造心形）或 SVG path，确保纯静态渲染、无外部资源依赖
- **无构建工具依赖**：不使用 Vite/React/框架，需求明确要求"可通过本地文件路径直接打开"

## 4. 运行方式

直接用浏览器打开 `index.html` 文件（`file://` 协议）即可查看效果。无需启动开发服务器、无需安装依赖、无需构建步骤。

## 5. 技术约束

- 单文件交付：HTML + 内联 CSS + 内联 JS（如有）
- 无外部 CDN、无网络请求、无字体文件依赖
- 无服务端、无 API、无数据库、无认证、无后台任务
- 浏览器兼容性：现代浏览器（Chrome/Edge/Firefox/Safari 最新版本）

## 6. 验收可重复性

AC-01 为纯渲染验证，无随机结果、无动画定时、无异步事件、无状态路径。打开页面即可确定性验证，无需预置状态或手动推进。
