# 502 静态错误页 需求

## 目标

提供一个 502 错误状态页（用户明确提出）。页面为纯静态网页，可直接在浏览器中打开查看，不依赖任何服务端（用户明确提出）。

## 范围与排除

- 范围内（用户明确提出）：一个可直接在浏览器中打开查看的 502 错误状态页。
- 明确非目标（用户明确提出不需要服务端）：不包含服务端程序、后端接口、服务端渲染与构建部署流程。
- 未规定：视觉风格、配色、插图、品牌文案、移动端适配与多语言支持。

## 核心行为与规则

- 页面为单个静态 HTML 页面，用户直接打开即可渲染完整的 502 错误提示，无需启动服务、无需构建、无需安装依赖（用户明确提出：不需要服务端）。
- 页面明确表达「502」错误状态，并配简短的中文错误说明，告知当前服务暂时无法访问（推荐基线，闭合「502 错误页」的核心表达缺口）。
- 页面仅使用页面内的 HTML/CSS 资源，不引用外部 CDN、字体或接口请求，保证离线与任意静态托管环境下同样可正常显示（推荐基线，保证「不需要服务端」这一约束可被观察）。
- 页面不发起任何后端请求，也不包含需要服务端配合的功能；页面内如提供「重试」或「返回上一页」一类操作入口，须为纯前端行为（推荐基线）。
- 页面布局在常见桌面浏览器窗口下居中显示、无横向滚动条（推荐基线）。
- 未规定：具体视觉风格、配色、插图、品牌文案、是否支持移动端适配、是否支持多语言。
