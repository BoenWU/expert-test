# 404 静态网页架构基线

## 需求基线引用

本设计基于已批准的需求基线 `docs/wi-t1000340/requirements.md`（sha256:6027445a7f00f324e46d5e2845299a1bd8b198843c5fdce4e59522446eba7970）。产品语义、业务规则与验收语义以该基线为准，本设计仅给出必要的技术承载方式，不扩展或重裁产品语义。

## 架构结论

- **路线**：纯静态单文件页面（simple-frontend 精简路线，无应用框架、无构建步骤、无包依赖）。
- **交付物**：一个自包含的静态 HTML 文件，实现入口为仓库根目录的 `404.html`，HTML 结构与 CSS 样式内联于同一文件，零外部资源（不引用 CDN、外链字体、外链图片或任何脚本依赖）。
- **选型原因**：需求明确规定"页面以静态网页文件交付，不依赖任何服务端程序、后端接口或运行时数据；直接在浏览器中打开该文件即可完整展示"。引入 React/Vite 等框架或任何构建流程都会增加对构建工具与开发服务器的依赖，违反该边界；单文件自包含是满足"file:// 直接打开完整展示"的最小技术承载。

## 页面与交互范围

- **展示内容**：显著的"404"标识、简体中文"页面未找到"提示文案，以及一句简短的辅助说明。
- **交互**：唯一交互入口为"返回首页"链接，`href` 指向站点根路径 `/`，与需求基线的返回引导一致；不引入其他导航、搜索或候选链接。
- **视觉**：内联 CSS 提供简洁清晰的排版与对比，保证以 file:// 离线打开时样式完整渲染，无任何运行时样式回退缺失。

## 浏览器状态与数据归属

- 页面为纯展示型，无任何数据读写：不使用 `localStorage`、`sessionStorage`、Cookie 或任何客户端存储，也不产生浏览器状态。
- 无服务端权威数据、无认证/权限、无后台任务、无外部集成、无跨用户/跨设备共享数据。

## 实现入口与运行方式

- **实现入口**：单文件 `404.html`（自包含 HTML + 内联 CSS，无 JS 依赖）。
- **运行方式**：直接在浏览器中打开该文件（file:// 方式）即可完整展示页面并使用返回首页入口，全程无需启动任何服务端；这是需求验收采用的运行方式。
- **可选部署形态**：该文件也可按静态托管平台的 404 页约定（如 `404.html` 命名）或服务器错误页配置部署到真实站点，此时"返回首页"链接自然指向站点根路径。部署形态仅为可选承载方式，不是验收必需条件。

## 设计边界

- 不引入任何服务端程序、API、数据库、构建工具链或运行时数据依赖。
- 页面文案语言默认为简体中文。
- "返回首页"链接目标为 `/`；若实际站点结构不同，可在实现时按需求基线约定调整链接目标，不改变其余设计决定。
