# 404 静态网页需求

## 目标

交付一个纯静态的 404 页面：用户到达不存在的页面时，看到明确的"页面未找到"提示并获得返回引导。页面不需要任何服务端，直接以静态文件方式打开即可完整展示。

## 核心行为与规则

1. 【用户明确提出】纯静态交付：页面以静态网页文件交付，不依赖任何服务端程序、后端接口或运行时数据；直接在浏览器中打开该文件即可完整展示。
2. 【用户明确提出】404 提示：页面显著展示"404"标识与"页面未找到"含义的提示文案。
3. 【推荐基线】返回首页引导：页面提供"返回首页"入口，指向站点根路径（/），帮助用户离开 404 状态。该入口为闭合核心目标的最小引导，不引入其他导航、搜索或候选链接；若实际站点结构不同，可调整链接目标。
4. 【假设，可调整】页面文案默认使用简体中文。

## 验收标准

### AC-01：无服务端直接打开 404 页面，呈现未找到提示并可返回首页

- 验收条件：以静态方式（直接打开文件）访问 404 页面，无需任何服务端即可看到 404 标识与页面未找到提示，且返回首页入口可用。
- 入口类型：用户界面
- 验证动作：在浏览器中直接打开交付的 404 页面静态文件（file:// 方式，不启动任何服务端），观察页面渲染结果；点击页面上的"返回首页"入口。
- 预期结果：
  1. 页面正常渲染，显著显示"404"标识与简体中文的"页面未找到"提示文案；
  2. "返回首页"入口存在且可点击，点击后浏览器离开当前 404 页面并指向站点根路径（/）。
- 证据类型：runtime-render, interaction
