# 需求文档：400 静态网页

## 目标

实现一个静态 HTML 网页，在浏览器中展示 HTTP 400 Bad Request 错误页面，向访问者传达请求无法理解或处理的信息。

> 用户明确提出：实现一个 400 静态网页。

## 核心行为

1. **错误码展示**：页面显著展示 HTTP 状态码 `400`。
2. **错误描述**：页面展示对应的错误标题（如 "Bad Request"）及简短说明，告知用户请求无法被服务器理解。
3. **静态页面**：页面为纯静态 HTML 文件，内嵌或链接 CSS 样式，不依赖任何后端服务、数据库或运行时环境。
4. **浏览器直接打开**：用户可通过浏览器直接打开该 HTML 文件查看页面内容，无需启动服务器。

## 约束

- 页面为单文件静态 HTML（可内联 CSS），不要求外部依赖。
- 不涉及服务端逻辑、路由配置或持久化。
- 未规定事项：具体视觉风格（配色、字体、布局细节）、是否包含返回首页链接、多语言支持等均未由用户明确提出，保持未规定。

## 验收场景

### AC-01：浏览器打开页面显示 400 错误信息
- 验收条件：静态 HTML 文件在浏览器中直接打开后，页面展示 HTTP 400 状态码及对应的错误说明文本。
- 入口类型：用户界面
- 验证动作：在浏览器中打开该静态 HTML 文件。
- 预期结果：页面可见 `400` 状态码数字和 "Bad Request" 相关的错误描述文本，页面有基本的可读样式。
- 证据类型：runtime-render, visual-style
