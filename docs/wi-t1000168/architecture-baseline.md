# 系统设计

本设计基于已批准的需求基线 `docs/wi-t1000168/requirements.md`（sha256: bcda2a53ca23342bda32eb62edd1600e700c50487681399791e7c703f2be74cf），将其中的 502 静态错误页需求落定为纯静态单文件实现。产品语义、范围与验收含义均以该基线为准，本文档不重复其业务规则、用户旅程或验收场景。

<!-- system-design: scope -->
## 1. 整体方案与设计基线

- 整体结论：纯静态单页面（simple-frontend）。不含服务端逻辑、API、数据库、认证、后台任务或外部集成，设计不引入任何额外基础设施或依赖包。
- 技术形态：交付一个自包含的 HTML 文件——样式以内联 `<style>` 块承载；使用系统字体栈（不引入外部字体）；如需装饰图形仅用 CSS 或内联 SVG；字符编码以 `<meta charset="utf-8">` 固定。页面无构建步骤、无包管理、无任何外部资源请求。
- 实现入口：工作区根目录的 `502.html`，是本任务唯一源文件与交付入口。
- 适用运行方式：桌面浏览器以本地文件协议（file://）直接打开；或经静态托管、配置为站点 502 错误页。两种方式呈现与交互完全一致，页面加载过程不发出任何服务端请求。无启动命令、端口、环境变量或服务进程。
- 交互边界：页面无表单输入、无本地存储、无状态持有；全部交互为浏览器原生行为（见第 2 章操作入口）。

## 2. 领域责任、模块边界与接口摘要

页面自包含，内部仅两块职责，无跨模块调用：

| 职责 | 内容 | 接口 / 触发点 |
| --- | --- | --- |
| 错误呈现 | 502 状态码、错误标题、中文说明 | 静态渲染，无接口 |
| 操作入口 | 刷新重试、返回首页 | 浏览器原生行为，见下 |

- 刷新重试：以极少量内联 JavaScript（`location.reload()`）实现，点击后重新加载当前页面；使用原生可聚焦元素渲染，支持键盘焦点访问。可选降级：指向页面自身文件名的链接具有等价的重载语义。
- 返回首页：普通 `<a href="/">` 链接，点击后向站点根路径导航；本地文件方式打开时目标地址可能不存在，按基线属预期行为，错误页不处理目标缺失。
- 数据与状态归属：页面不拥有任何状态或数据；502 故障的发生与恢复由外部网关/上游服务决定并归其所有，不在本系统边界内。
- 不存在 API、Service 或数据访问层，设计中不虚构任何服务端接口。

## 3. UI 基线

- 布局：桌面浏览器下主体内容居中排布；错误主体（状态码、标题、说明、两个操作入口）首屏完整可见，无需滚动。
- 信息层级：`502` 状态码为最醒目视觉元素；中文错误标题为主（可辅 "Bad Gateway" 英文副标题）；附一段面向普通访客的简短中文说明；浏览器标签页标题（`<title>`）体现 502 主题。
- 视觉方向：克制的错误页版式，单色调基底加一个强调色；系统字体；图形仅用 CSS 或内联 SVG；不依赖图标库、外部图片或网络字体。
- 状态策略：本页只有错误呈现一种状态，无加载、空数据、权限或动态内容变化状态。
- 边界：文案具体措辞与视觉比例细节由实现阶段按需求基线的推荐基线与验收条件落实，本设计不重写文案语义。
