# 502 静态错误页 需求基线

- 工作项：wi-t1000504（T1000504 实现一个502 静态网页）
- 决策：ready

## 1. 目标

提供一个表示网关错误的 502 错误页面，以纯静态网页形式交付，不依赖任何服务端程序即可呈现。

## 2. 需求来源划分

**用户明确提出**

- 交付物是一个 502 错误页面。
- 采用静态网页方式实现。
- 不需要服务端。

**推荐基线（为闭合核心目标所必需，保守且可逆）**

- 页面为自包含的单页静态文件：样式内联，不引用外部脚本、样式、字体或图片资源，因此无需服务端、无需构建步骤即可直接在浏览器中打开。
- 页面文案使用中文，并明确标识 502 与 Bad Gateway 的含义，同时给出面向访问者的简短说明（服务暂时不可用，可稍后重试）。
- 页面以整页错误提示形式呈现，即在常规视口中首屏即可看到状态码与说明，而不是只有裸文本。

**未规定（本次不纳入基线）**

- 具体配色、字体、插画、品牌标识与视觉风格细节。
- 是否提供“重新加载”“返回首页”等交互入口。
- 多语言、SEO、访问统计、可访问性等级目标。
- 页面文件名与部署位置。

## 3. 核心行为与规则

1. 页面是一个可直接打开即渲染的静态网页，不发起服务端请求，不依赖任何外部网络资源。
2. 页面必须同时呈现：502 状态码标识、Bad Gateway（网关错误）含义、简短的原因说明与后续操作建议。
3. 页面在无网络、无服务端的环境中打开时，内容与样式与联网时一致。
4. 页面在常见桌面与窄屏视口下，文字不溢出容器、不出现横向滚动，主要内容完整可读。

## 4. 验收场景

### AC-01：直接打开静态页面即可看到 502 错误提示
- 验收条件：页面以静态文件形式打开后，首屏可见 502 状态码标识、Bad Gateway 含义说明和面向访问者的简短建议。
- 入口类型：用户界面
- 验证动作：在浏览器中直接打开该静态页面文件。
- 预期结果：页面正常渲染为错误提示页，上述三类信息均可见且语义正确。
- 证据类型：runtime-render

### AC-02：无服务端、无外部网络依赖时呈现一致
- 验收条件：在未启动任何服务端、且不可访问外部网络的条件下，页面内容与样式完整呈现，无资源加载失败导致的缺样式或缺内容。
- 入口类型：用户界面
- 验证动作：在离线且无本地服务的环境中直接打开该静态页面文件。
- 预期结果：页面外观与信息完整度与常规环境打开时一致，控制台无因外部资源请求失败而影响呈现的错误。
- 证据类型：runtime-render, visual-style

### AC-03：不同视口下内容完整可读
- 验收条件：页面在常规桌面视口与窄屏视口下，正文不溢出容器、无横向滚动，502 状态码与说明文字完整可读。
- 入口类型：用户界面
- 验证动作：打开该静态页面，并分别以宽屏与窄屏视口观察页面内容。
- 预期结果：两种视口下主要内容均完整显示，文字不截断、不重叠、不横向溢出。
- 证据类型：visual-style
