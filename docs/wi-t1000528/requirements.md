# 需求：403 静态网页

## 目标

提供一个 403 Forbidden 静态错误页面，用户在浏览器中直接打开即可看到"禁止访问"的提示信息。无需服务端，页面为纯静态 HTML（可含内联 CSS / JS），不依赖后端接口、数据库或构建服务。

## 核心行为与规则

- **页面类型**：纯静态 HTML 文件，浏览器直接打开 `403.html`（或等价入口文件）即可渲染，不依赖服务端。
- **HTTP 语义**：页面用于表达"禁止访问（403 Forbidden）"语义；页面标题（`<title>`）包含 `403`，正文显式展示 `403` 状态码与"禁止访问"含义的提示文案。
- **可见内容**（用户明确提出）：
  - 显著的 `403` 数字 / 状态码；
  - 一句"禁止访问"或等价说明文案；
  - 提示用户无权访问当前资源。
- **静态约束**：不发起任何后端请求、不依赖运行时构建服务；所有样式与脚本内联或为本地静态资源。页面离线可正常显示。
- **未规定事项**：具体视觉风格、配色、图标、文案措辞、是否提供"返回首页"按钮、多语言、响应式断点均未由用户指定，保持未规定，由实现阶段决定，不作为正式验收项。

## 验收场景

### AC-01：浏览器直接打开静态页面即可看到 403 禁止访问提示
- 验收条件：作为纯静态资源，页面在浏览器中直接打开后渲染出 403 Forbidden 相关内容。
- 入口类型：用户界面
- 验证动作：在浏览器中直接打开该静态 HTML 文件（不经过服务端）。
- 预期结果：页面正常渲染，标题包含 `403`，正文显式展示 `403` 状态码与"禁止访问"含义的提示信息，且不依赖任何后端请求即可完整呈现。
- 证据类型：runtime-render
