# 502 静态网页架构基线

本设计以已批准的需求基线 `docs/wi-t1000029/requirements.md`（sha256:a0049fdd866be7b8b51ce7e4af16964efca9a8a878da2ca7ba29ce9b980f3c16）为唯一产品范围来源，只补充必要的技术承载方式，不扩展或重裁产品语义。

## 架构路线

- 分类结论：`simple-frontend`（紧凑路线）。
- 依据：需求明确要求静态网页且不需要服务端；页面不依赖后端接口、不发起后端请求，无权威数据、认证、后台任务、外部集成与共享数据需求。
- 因此不引入服务层、数据库、认证、任务调度与外部集成，也不生成技术契约、工作区引导文件或 ADR。

## 页面与交互范围

- 单页面错误页，一次性呈现，无多路由、无导航。
- 页面内容限定为：502 状态码、`Bad Gateway` 标识、中文说明（服务暂时不可用、请稍后重试）、静态重试指引文字。
- 交互仅为静态呈现；不放置依赖后端能力才能工作的操作，避免错误页本身再次失败。
- 不新增品牌、具体业务、运营信息、语言切换或上报采集等需求未覆盖的内容。

## 数据与状态归属

- 页面无业务数据、无持久化、无浏览器存储写入：`localStorage`/`sessionStorage`/Cookie 均不使用。
- 页面状态完全由静态内容决定，刷新或重新打开后表现一致，不存在跨页、跨设备或跨用户的共享数据。

## 实现入口与运行方式

- 技术形态：Vite + React 单页应用，入口为根目录 `index.html`（挂载 `src/` 下的 React 根组件）。
- 开发运行：`npm run dev`（Vite 开发服务器）。
- 构建：`npm run build` 输出 `dist/index.html`。
- 关键构建约束（保证"直接打开即完整呈现"）：
  - `base: './'`，产物资源使用相对路径；
  - `vite-plugin-singlefile` 内联全部脚本与样式，配合 `cssCodeSplit: false` 与较大的 `assetsInlineLimit`，使 `dist/index.html` 成为自包含单文件；
  - 不引入外部字体、CDN、图标库或任何 `http(s)` 外链资源，视觉资源全部由内联 CSS/内联 SVG 提供。
- 交付产物即为该自包含单 HTML 文件，可直接以本地文件方式（`file://`）打开，无需任何服务端支持。

## UI 方案

- 本页属独立错误页，不是管理工作台，不采用 Ant Design 组件体系，避免为单页错误提示引入组件库与额外样式体积。
- 视觉方向：中性底色 + 居中内容区的大号 502 数字、清晰的 `Bad Gateway` 状态标识、一行主说明与简短重试指引；使用系统字体栈与克制的排版层级，兼顾桌面与移动视口（响应式折行、字号缩放）。
- 视觉语言与同项目既有 500 错误页保持一致的中性、可读风格，但不复用其页面内容，也不处理需求明确排除的多错误页统一与复用。

## 部署基线

- 已按前端部署基线初始化 `deploy/Dockerfile` 与根目录 `.dockerignore`；镜像以 Node 构建、Nginx 托管 `dist` 静态文件。
- 部署文件只是工作区基线，不构成本设计文档的产物；页面本身的验收不依赖镜像运行，直接打开构建产物即可验证。

## 验证边界

- 页面无动画、随机结果、定时任务与外部异步事件，所有呈现由确定静态内容决定，无需预置状态、固定结果或测试控制入口；正常行为即验证路径。
- AC-01：直接以本地文件方式打开构建产物，检查首屏标识与中文说明、重试指引完整可读。
- AC-02：检查构建产物为自包含单文件（无外链脚本、样式、字体、图片引用），并在无服务端环境中打开确认无后端请求与请求失败提示。
