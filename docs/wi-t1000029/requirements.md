# 502 静态网页需求

## 目标

提供一个 502 错误页，在服务暂时不可用（坏网关）时向访问者说明当前状态，并给出后续处理指引。页面为静态网页，不依赖任何服务端即可使用。

## 核心行为与规则

- 页面用途（用户明确提出）：作为 502 错误页呈现给访问者。
- 交付形态（用户明确提出）：静态网页；用户明确提出不需要服务端。
- 页面内容（推荐基线）：页面以 502 状态码与 "Bad Gateway" 作为明确标识，并配一段中文说明，表述服务暂时不可用、稍后重试；该文案为最小可读说明，不涉及品牌、具体业务或运营信息。
- 运行方式（推荐基线）：页面文件可直接打开即完整呈现，不依赖后端接口、不发起后端请求；因而不存在"服务不可用时页面自身也加载不出来"的情况。
- 访问者引导（推荐基线）：页面提供一段静态的重试指引文字；不放置依赖后端能力才能工作的交互，避免错误页本身再次失败。

未规定事项（不做推断）：视觉风格与配色、品牌标识与文案署名、部署地址与访问域名、语言切换、其他错误状态页（如 500、404）的复用与统一、页面是否需要收集上报信息。

## 验收场景

### AC-01：直接打开即呈现完整的 502 错误页
- 验收条件：在没有任何后端服务运行的环境中直接打开该页面，页面完整呈现 502 标识、Bad Gateway 标识与中文说明文案，且附带重试指引。
- 入口类型：用户界面
- 验证动作：直接打开交付的页面文件，观察首屏内容。
- 预期结果：首屏可见 502 与 Bad Gateway 标识及中文说明文案，文案完整可读，无空白区块、无持续加载状态、无报错占位。
- 证据类型：runtime-render, visual-style

### AC-02：页面运行不依赖服务端
- 验收条件：页面在没有任何服务端支持的环境下可正常呈现；打开页面过程中，页面自身不发起针对后端接口的网络请求。
- 入口类型：用户界面
- 验证动作：在无服务端运行的环境中打开页面并观察其网络请求。
- 预期结果：页面内容正常呈现，未出现因服务端缺失导致的请求失败提示；页面所需资源均随页面本地提供，不请求后端接口。
- 证据类型：runtime-render, other
