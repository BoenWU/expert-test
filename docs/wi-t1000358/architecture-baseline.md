# 403 Forbidden 静态网页 — 架构基线

## 需求基线

- 批准需求快照：`docs/wi-t1000358/requirements.md`（SHA-256 校验通过）
- 内部覆盖清单：AC-01（浏览器直接打开静态文件可见 403 禁止访问提示）
- 本次设计无 `designChangeRequest`，无额外设计约束。

## 路线结论

- 应用类型：`simple-frontend`（compact 精简路线）
- 依据：需求明确交付纯静态、自包含单文件 HTML，`file://` 直接打开即渲染；范围外已排除全部服务端能力。无数据存储、认证、后台任务、外部集成或共享数据需求，因此连浏览器本地存储都不需要。

## 页面与交互范围

- 交付物为单个自包含 HTML 文件：结构与样式全部内联于该文件（内联 CSS），不引用任何外部 CSS/JS/图片/字体等资源，无网络请求。
- 页面内容：
  - 醒目的 "403" 状态标识（大号数字作为视觉主体）；
  - 表达"禁止访问 / 无权访问该资源（Forbidden）"含义的标题与说明文案；
  - 简单的静态视觉层次（标识、标题、说明），样式克制、可扫描。
- 交互范围：纯静态展示，无任何 JavaScript 脚本逻辑，避免脚本错误，直接满足 AC-01 的"无脚本错误"条件。
- 不设导航跳转、表单、按钮等交互组件（需求未要求，避免扩展产品语义）。

## 浏览器状态与数据归属

- 无任何数据：不使用 `localStorage`、`sessionStorage`、`Cookie` 或 `IndexedDB`。
- 页面无状态、无会话：打开即完成渲染，关闭即结束；同一浏览器或设备间不存在任何数据共享或同步。
- 页面不发起任何后端接口请求，也不依赖任何外部服务。

## 实现入口与运行方式

- 实现入口：仓库根目录下的单一 HTML 文件（实现阶段创建，建议文件名 `403.html`），这是唯一用户交付物。
- 运行方式：用户在浏览器中以 `file://` 方式直接打开该文件即可看到 403 禁止访问提示；无需构建步骤、无需包管理器、无需启动任何服务端进程。
- 文件约定：
  - UTF-8 编码，包含 `<meta charset="UTF-8">`，保证中文文案正常显示；
  - 包含 `<title>`（含 403/禁止访问语义）与标准 HTML5 文档结构；
  - 内联样式做基础响应式处理（视口宽度自适应），保证桌面与常见窗口宽度下可读。

## 技术承载边界

- 不引入前端框架、构建工具或任何包依赖（需求明确无需构建步骤）。
- 不虚构服务/API、数据库、认证、后台任务、外部集成或同步层；范围外约束（无服务端程序、API 或数据存储）由"纯静态单文件"承载方式天然满足。
- 唯一实现性产物是上述 HTML 文件；本阶段不产生技术契约、工作区初始化或 ADR。
