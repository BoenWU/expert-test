# 403 Forbidden 静态网页需求

## 目标

交付一个 403 Forbidden（禁止访问）静态网页：用户直接在浏览器打开该文件即可看到无权访问的提示页面，全程无需启动任何服务端程序。（用户明确提出）

## 核心行为与规则

1. 页面以单个自包含 HTML 文件交付，样式内联在文件内，无需构建步骤、无需部署任何服务端即可使用。（用户明确提出：不需要服务端）
2. 在浏览器中以本地文件方式直接打开（file:// 打开）即可正常渲染，页面不依赖任何后端接口请求。（用户明确提出）
3. 页面核心展示内容：明显的 "403" 状态标识，以及表达"禁止访问 / 无权访问该资源"含义的提示文案。（用户明确提出：403 Forbidden 页面）

## 范围外

- 服务端能力：不含任何服务端程序、API 或数据存储，仅静态展示。（用户明确提出并排除）

## 验收场景

### AC-01：浏览器直接打开静态文件可见 403 禁止访问提示
- 验收条件：在无任何服务端进程运行的情况下，浏览器直接打开交付的 HTML 文件，页面完整渲染出 403 禁止访问提示。
- 入口类型：用户界面
- 验证动作：在浏览器中直接打开（file:// 方式）交付的 HTML 文件，观察页面渲染结果。
- 预期结果：页面正常渲染，非空白、无脚本错误；可见明显的 "403" 标识及表达"禁止访问"（Forbidden）含义的提示文案。
- 证据类型：runtime-render, visual-style
