# 架构基线：500 静态网页

## 依据

本设计遵循已批准的 [需求基线](requirements.md)，不扩展或重裁其中的产品语义。产品范围只有一件事：一个打开即呈现 500 服务器错误提示的静态页面，且不依赖服务端。

## 路线结论

应用类型：`simple-frontend`（精简前端路线）。

判定依据：需求明确要求页面由浏览器直接加载本地文件即可完整显示，不依赖服务端渲染、接口请求或后台进程；未涉及权威数据存储、认证权限、后台任务、外部集成或跨用户/设备共享。因此技术承载方式为纯静态单页前端，不引入服务端、数据库、认证或同步层。

## 页面与交互范围

- 单一页面，无需路由：页面本身就是错误提示页，所有访问者看到同一内容。
- 首屏即完整呈现：不需要任何交互、加载态或数据请求即可显示错误码与说明文案。
- 交互边界：需求基线未规定跳转入口（返回首页、重试等），设计不新增此类入口；页面为纯展示，不含表单、数据写入或状态流转。
- 响应式要求：按需求基线只需在常见桌面窗口下清晰、无遮挡、无横向滚动；不做移动端专项适配，但布局以居中、流式宽度实现，窄屏不会溢出。

## 浏览器状态与数据归属

- 无业务数据、无持久化：不写入 `localStorage`，不读写 Cookie，不发起任何网络请求。
- 页面全部内容为随文件提供的静态文案与样式，渲染结果只取决于页面文件本身，刷新或重开表现一致。
- 由于没有数据边界，也不存在跨浏览器、跨设备或跨用户共享问题。

## 技术选型

| 关注点 | 结论 |
| --- | --- |
| 应用形态 | React + Vite 单页应用（新建应用基线），构建产物为纯静态资源 |
| 路由 | 不使用路由库，单一入口组件直接渲染错误页 |
| 组件体系 | 不使用 Ant Design 等组件库：本页是单一错误提示版式，无表格、表单、导航等工作台结构，引入组件库只会增加体积与依赖 |
| 样式方案 | 页面级 CSS（普通样式表），不引入外部 CSS 或字体 CDN，全部资源随构建产物提供 |
| 资源与自包含 | 不使用外部网络资源；图标如需使用以内联 SVG 实现，字体走系统字体栈，保证离线打开与联网表现一致 |
| 服务端 | 无。无接口层、无服务端渲染、无后台进程 |
| 部署基线 | 已生成 `deploy/Dockerfile` 与根目录 `.dockerignore` 作为静态托管的可选基线；页面本身不依赖它们即可本地打开 |

## 视觉方向

- 居中单列排版：错误码「500」作为视觉主体（大字号、强对比），下方依次为错误标题与简体中文说明文案。
- 配色克制：中性浅色背景、深色文字，辅以单一强调色标识错误状态；不依赖图片素材。
- 可读性优先：正文尺寸与行高保证常见桌面窗口下清晰可读，纵向内容较高时允许纵向滚动，禁止横向滚动。
- 文案使用简体中文，错误码固定为「500」。

## 实现入口与运行方式

- 实现入口：Vite 标准结构，`index.html` 作为页面入口，挂载 React 根组件（`src/main.jsx`）渲染错误页；具体组件拆分、样式文件与文案常量在实现阶段按此基线落地。
- 本地运行：`npm install` 后执行 `npm run dev`，由 Vite 开发服务器提供预览；`npm run build` 输出静态产物，可直接用浏览器以本地文件方式打开验证离线表现。
- 无环境变量、无接口地址配置，运行不需要任何后端服务。

## 验收覆盖要点（内部清单）

- AC-01（错误码与说明文案首屏可见）：由单一静态入口组件 + 居中排版样式保证，实现阶段以浏览器打开页面核对文案与版式。
- AC-02（无服务端与外部网络资源依赖）：由零网络请求、零外部资源、系统字体栈与内联资源保证，实现阶段在未启动任何服务的条件下以本地文件方式打开验证；构建产物中不出现外部域名引用。

## 边界说明

- 本阶段不落地页面代码、不填充具体文案措辞，这些属于实现阶段工作。
- 需求基线中标注「未规定」的事项（文件名与存储位置、跳转入口、移动端专项适配、品牌规范）在本基线中同样不作约束，也不作为验收依据。
