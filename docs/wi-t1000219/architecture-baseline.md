## 1. 整体方案与设计基线

交付物是一个纯静态 404 错误页面：单个 HTML 文件 `404.html`，样式随文件一同交付（内联于同一文件），不含任何需要服务端处理的内容，不依赖构建步骤、外部请求或脚本框架。打开页面即呈现完整布局。

技术栈与形态结论：

- 形态：单文件静态页面（HTML + 内联 CSS），无 JavaScript 依赖，无服务端程序、服务端路由与服务端渲染；
- 文件命名：按需求推荐基线 R-01 命名为 `404.html`，与静态托管约定一致，同时可用本地文件方式直接打开；
- 首页入口：页面"返回首页"入口默认指向站点根路径 `/`；若交付时站点结构不同，以实现阶段确认的地址为准，本范围不变；
- 设备基线：桌面 Web，按主流桌面浏览器（Chrome、Edge、Firefox 当前稳定版）默认窗口尺寸验收；无横向滚动、无元素遮挡、入口可点击区域清晰可辨；窄屏适配不在当前验收范围；
- 部署形态：任意静态托管环境（静态网站托管、对象存储、CDN 等）或本地文件打开，部署目标待定、部署时确认，不在本阶段固定。

设计不引入数据库、缓存、后台任务、外部服务、认证或日志上报等任何服务端能力；产品语义（404 标识、提示文案、返回首页入口）完全沿用已批准需求，不重新裁定。

## 2. 领域责任、模块边界与接口摘要

本设计只有一个内部单元，不拆分模块层，不定义 API 或数据访问层：

- 模块 M-01（404 错误提示展示）：唯一载体为 `404.html` 自身。职责：首屏显著展示"404"错误标识与简体中文提示文案（语义友好，例如"抱歉，您访问的页面不存在"），打开即可见、无需滚动；核心事实唯一归属为静态文件内容，无其他数据源。
- 模块 M-02（导航与恢复操作）：同一页面内的"返回首页"入口（链接或按钮形态），职责：点击后浏览器跳转到站点首页地址（默认 `/`）；入口文字清晰表明其作用是返回站点首页。
- 模块 M-03（静态样式呈现）：样式随静态文件交付，打开即完整呈现；无构建、无外部资源依赖。

浏览器本地状态与数据归属：页面无状态、无本地存储写入、无动态数据读取；除页面自身静态内容外不存在任何数据 owner，也不存在模块间接口调用。页面与外部的唯一边界是"返回首页"链接触发的浏览器跳转。

## 3. UI 基线

需求包含用户界面，按需求 R-02 冻结以下全局 UI 结论（需求只约束可验收结果，视觉风格由本设计确定）：

- 布局：单屏居中布局，桌面视口默认尺寸下一屏完整呈现，不产生横向滚动；
- 视觉风格：克制的错误页风格，以醒目"404"字样为视觉焦点，搭配说明文案与主操作入口；配色、字体与图标/插画细节由实现阶段在本基线内执行，不引入外部视觉资源依赖；
- 状态策略：页面为静态内容，无加载态、空数据态或权限态；仅存在"页面不存在"一种内容状态；
- 目标设备：桌面 Web 默认基线，沿用当前可用桌面视口进行真实页面验收，不强制固定尺寸。

## 4. 运行与可靠性

- 运行方式：将 `404.html` 放入静态托管环境，或以本地文件方式直接在浏览器打开，两种方式下页面功能完整可用，全过程无需服务端参与；
- 兼容性：不依赖任何特定浏览器 API，使用主流桌面浏览器均支持的标准 HTML/CSS，无影响展示的脚本错误（页面不含脚本，天然无脚本错误面）；
- 性能：单文件轻量静态资源，首屏内容随文件下载后立即可见；无量化性能验收要求；
- 可靠性边界：无外部服务依赖，无网络请求失败面；页面不承诺服务端 404 状态码行为（需求明确不做）。

## 5. 架构决策

本设计不存在改变系统边界、数据权威、权限、外部依赖或迁移方式的取舍；技术形态由需求（纯静态、无服务端）直接确定，不新增 ADR。
