# 需求文档：404 静态网页

## 目标

创建一个静态 404 错误页面，当访问者进入不存在的路径或资源时展示该页面，告知用户页面未找到并提供返回入口。

> 用户明确提出：创建一个 404 静态网页。

## 核心行为与规则

1. **页面展示 404 状态**：页面以醒目方式展示「404」标识和「页面未找到」的提示文案，使用户能直观理解当前状态。
2. **纯前端静态页面**：页面为单一 HTML 文件（可内联 CSS），不依赖服务端逻辑、数据库或外部接口。
3. **返回首页入口**：页面提供一个可点击的链接或按钮，指向站点根路径（`/`），方便用户返回首页。
4. **自适应布局**：页面在常见桌面和移动浏览器宽度下均可正常显示，内容居中布局。

> 以上规则中，第 1–3 条为用户目标直接推导的核心行为；第 4 条为推荐基线，确保页面在常见设备上可用，可由后续阶段调整。

## 验收标准

### AC-01：访问者看到 404 页面并可返回首页
- 验收条件：在浏览器中打开 404 页面文件后，页面展示「404」标识与「页面未找到」提示，并提供一个指向根路径的返回入口。
- 入口类型：用户界面
- 验证动作：在浏览器中直接打开 404 页面 HTML 文件，观察页面内容。
- 预期结果：页面可见「404」标识和未找到提示文案；页面中存在一个可点击的返回首页链接，其 `href` 指向 `/`。
- 证据类型：runtime-render, visual-style
