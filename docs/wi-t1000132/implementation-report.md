- 交付物：工作区根目录 `404.html`（单文件静态页面）

## 1. 变更行为与实现依据

本阶段交付一个自包含的静态 404 提示页面 `404.html`：访问者打开页面后立即看到大号“404”标识与“页面未找到”中文提示，并通过“返回首页”入口（指向站点根路径 `/`）离开错误页。页面不含任何服务端程序、脚本或外部资源，直接以 file:// 方式打开即可完整显示。

实现依据为已批准的需求快照与架构基线（simple-frontend 精简路线）：批准需求要求“页面不需要任何服务端程序支持，直接在浏览器中打开即可正常显示”（AC-04），且离线断网时仍完整显示（推荐基线）；架构基线据此冻结为“原生 HTML5 + CSS 单文件、零 JavaScript、零外部资源”的最小实现。本次实现未引入新缺陷修复类变更，`rootCause` 即上述用户目标与约束的落地。

## 2. 实现范围

源码变更仅一处：新增 `404.html`（工作区根目录）。工作区此前无任何源码、依赖配置或构建链，属新建交付，无既有行为兼容负担。

页面内部结构（对应架构基线的两个语义分区）：

| 分区 | 需求模块 | 实现方式 |
| --- | --- | --- |
| 提示区 | M1 错误提示展示 | `<main class="error-page">` 内 `p.error-code` 渲染大号加重“404”标识（第一视觉焦点）；`h1.error-title` 为“页面未找到”；`p.error-desc` 为“当前地址不存在或已被移除，请检查链接是否正确。” |
| 操作区 | M2 离开错误页入口 | 原生超链接 `<a class="btn-home" href="/">返回首页</a>`，按钮式实底视觉，支持鼠标点击、Tab 键盘聚焦与 Enter 触发 |

样式与语义约束：

- 全部样式内联于 `<style>` 元素；系统字体栈（PingFang SC / Microsoft YaHei / Segoe UI 等）；未引用任何外部 CSS、字体、图标、图片或脚本资源。
- 文档声明 `lang="zh-CN"` 与 `<meta charset="utf-8">`；`<title>404 · 页面未找到</title>`。
- 布局为单列垂直内容流，`body` 以 grid 在视口内居中，未锁定固定视口尺寸，适配架构基线的桌面目标设备设定。
- `:focus-visible` 焦点环满足键盘可达要求；未使用表情符号或 Unicode 图形充当图标、装饰或导航元素。
- 无状态、无数据读写、无脚本拦截；file:// 场景下点击“返回首页”后由浏览器按自身行为呈现根路径目标，页面自身不报错（架构基线规定行为）。
