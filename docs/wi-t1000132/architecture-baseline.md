## 1. 整体方案与设计基线

本工作项交付一个自包含的静态 404 页面文件：工作区根目录下的 `404.html`。全部样式内联于该文件的 `<style>` 元素，不引用任何外部 CSS、字体、图标、图片或脚本资源，不包含服务端程序、构建链或包管理依赖。

技术栈结论与依据：

- 形态：原生 HTML5 + CSS 单文件，零 JavaScript、零外部资源。批准需求快照要求页面在“本地仅持有页面文件、无服务端环境”时直接用浏览器打开即完整显示（静态可用性为用户提出约束），离线断网时仍完整显示（推荐基线）；页面无状态、提示内容固定（推荐基线）。单文件静态 HTML 是同时满足全部约束的最小实现。
- 不引入 React/Vite 等框架或脚手架：本交付物是单页静态错误提示页而非应用，无状态管理、无交互逻辑、无数据加载；框架与构建链没有任何需求证据支撑，且默认构建产物无法在无服务端的 file:// 场景直接打开。页面全部行为由静态标记与一个原生超链接承担。
- 不生成 technical-contract.md 与 workspace-bootstrap.json：不存在前后端 API 契约，不执行 workspace 初始化，不选择任何公共模块。

运行方式（冻结）：

- 正常打开：直接用浏览器打开 `404.html`（file:// 协议），提示内容与样式即时完整呈现，无需等待、无需交互、无可见加载过程。
- 托管场景（不在本工作项范围内）：`404.html` 可直接放置于任意静态站点根目录充当 404 页；页面自身不感知托管方式，也不随托管方式变化。
- 无服务端参数：不存在端口、进程、数据库路径或环境变量；任何服务端配置（404 状态码下发、路由重写、重定向规则）均不在交付范围内。

浏览器本地状态与数据归属：

- 页面无任何数据读写：不使用 localStorage、sessionStorage、Cookie 或 IndexedDB；不存在表单、运行时输入或提交行为。
- 页面呈现内容由静态标记唯一决定，运行时不发生变化；唯一外向行为是“返回首页”链接导航，目标地址由该链接的 href 静态声明。

## 2. 领域责任、模块边界与接口摘要

<!-- system-design: architecture-boundaries -->

单文件内部按语义分区承载两个需求模块，无跨模块调用、无共享状态、无运行时接口：

| 内部分区 | 职责 | 数据/事实归属 | 对外行为 |
| --- | --- | --- | --- |
| 提示区（承载 M1） | “404”标识与“页面未找到”中文提示文案的静态展示 | 内容为静态标记，无运行时数据来源 | 无，纯展示 |
| 操作区（承载 M2） | “返回首页”入口 | 目标地址静态声明为站点根路径 `/` | 原生超链接 `<a href="/">`，鼠标点击或键盘聚焦后回车均触发浏览器导航 |

边界与失败行为：

- 提示内容无交互前置：页面加载完成即完整呈现，不存在需要脚本填充、延迟出现或等待请求的占位状态。
- “返回首页”入口使用原生超链接元素，天然支持键盘 Tab 聚焦与 Enter 触发，满足可识别的可点击视觉表现与键盘可达要求；不使用脚本拦截或模拟跳转。
- 当目标首页地址在当前环境中不存在（例如以 file:// 方式直接打开页面时 `/` 无对应目标），点击后由浏览器按自身行为呈现目标地址结果，页面自身不报错、不产生错误分支、不做脚本兜底。
- 页面无生命周期状态转换，自身不产生需要用户处理的错误状态。

## 3. UI 基线

- 目标设备：桌面 Web 浏览器（需求基线默认）；不做移动端/窄屏专项适配（需求明确排除范围）。布局按视口居中，在常见桌面窗口尺寸下正常呈现即可，不锁定固定视口尺寸。
- 布局：单列垂直内容流，内容块在视口内水平居中、垂直方向充足留白居中呈现；内容自上而下依次为“404”标识 → 提示文案 → 返回入口，元素间距固定，无重叠、无浮动、无滚动布局。
- 视觉方向：“404”标识使用大号加重字形，构成页面第一视觉焦点；提示文案使用常规正文字号并保证足够对比度可读；返回入口采用按钮式视觉（实底或描边样式）明确可点击性，并具备可见的键盘焦点样式（焦点环）。
- 样式实现约束：全部规则内联于单文件 `<style>`；使用系统字体栈，不引入外部字体、图标库或图片资源（离线可显示约束）；不使用表情符号或 Unicode 图形充当图标、装饰或导航元素。
- 语言与语义：文档声明 `lang="zh-CN"`；文案为中文，核心提示语义固定为“页面未找到/当前地址不存在”。
- 状态策略：页面为最终态静态展示（其本身即错误提示页），不存在加载、空数据、错误或无权限状态的切换与转场。
