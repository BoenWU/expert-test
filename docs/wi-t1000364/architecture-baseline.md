# 架构基线：服务访问 500 静态网页

> 工作项：wi-t1000364 ｜ 阶段：design ｜ 路线：simple-frontend（compact）

## 1. 需求基线引用

本设计基于已批准的需求基线 `docs/wi-t1000364/requirements.md`（sha256:927b4d7546c8af2d1c89307c4f1fd99d09e4c9a0c688c1e7ad73ad9475a13bf1）。需求核心：交付一张呈现 HTTP 500（服务器内部错误）语义的静态错误网页，页面自包含、不依赖任何服务端程序，直接在浏览器中打开即可完整呈现。

## 2. 页面与交互范围

- 交付物为**单个自包含静态 HTML 文件**，页面呈现"500 服务器内部错误"的语义提示（含状态码"500"与错误含义的标题/说明文案）。
- 页面为纯展示型：无表单、无用户输入、无脚本逻辑、无网络请求、无运行时数据读写。
- 是否提供"返回首页"等操作入口由实现阶段自行决定（需求未规定）；若提供，仅作为页内静态链接，不引入动态行为。
- 视觉样式与文案措辞（中文表述、配色、布局）由实现阶段在需求允许范围内自行决定。

## 3. 浏览器状态与数据归属

- 页面为**无状态展示页**：不使用 localStorage、sessionStorage、Cookie 或任何本地/远端存储，无浏览器状态需要管理。
- 无数据归属问题：页面不产生、不消费、不持久化任何数据，不存在跨浏览器/设备/用户的数据边界。

## 4. 技术选型与实现入口

- **技术形态**：单文件静态 HTML，样式以文件内 `<style>` 内联提供，不引用外部 CSS、字体、图片或脚本资源。
- **选型理由**：需求明确要求页面自包含且"直接在浏览器中打开页面文件即可完整呈现"（不启动、不依赖任何服务端）。单文件 HTML 在 `file://` 协议下由浏览器直接渲染，无模块加载、跨域或资源路径风险，是该约束下的最小技术承载。
- **不采用 React/Vite SPA**：本需求无任何数据交互、状态管理或组件复用需求；SPA 方案需要构建流程，且产物依赖资源加载路径，与"直接打开单文件即可呈现"的需求约束不匹配。
- **实现入口**：一个 HTML 文件（具体文件名与存放路径由实现阶段在授权源码写范围内确定），实现阶段只需产出该文件本身。

## 5. 运行方式

- **运行入口**：直接在浏览器中打开该 HTML 文件（`file://` 协议）即可完整呈现页面内容。
- **无构建、无启动命令**：不需要开发服务器（不运行 Vite dev server）、不需要 npm 安装或构建流程、不部署任何服务端程序。
- 托管与部署方式未在需求中规定；如后续用户提出托管诉求（例如作为某 Web 服务的 500 错误页被网关引用），由用户另行决定，不在本基线范围内。

## 6. 设计边界

- 服务/API、数据库、认证、后台任务、外部集成与同步层在需求与技术形态上均被排除，设计中不存在此类组件。
- 本基线冻结"单文件自包含静态 HTML"的技术结论，供后续实现阶段直接使用；实现阶段只需遵循该承载形态，页面文案与视觉细节在需求允许范围内自行决定。
