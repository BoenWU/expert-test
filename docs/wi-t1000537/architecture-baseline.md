# 架构基线：404 静态网页

## 需求基线引用

本设计基于已批准的需求快照 `docs/wi-t1000537/requirements.md`（sha256: `3fde8ea24a95d7abf23cafb232293fe367bd00aace1c3c94d5aa962e32c80352`）。产品范围：提供一个静态 404 错误页面，纯静态 HTML，不需要服务端逻辑。

## 应用类型

`simple-frontend`（compact 路线）。需求明确排除服务端逻辑、权威数据库、认证、后台任务、外部集成与跨用户共享数据。

## 页面与交互范围

- 单一 HTML 文件（`404.html`）作为唯一交付物，内含结构与内联样式，可选少量内联脚本。
- 页面展示"404"状态码与"页面未找到"提示文案。
- 页面提供返回首页的链接（`<a href="/">`），指向站点起始页。
- 基础响应式样式：通过 viewport meta 与 CSS 媒体查询，保证桌面与移动端均可正常查看。
- 视觉风格、配色、字体由实现自行决定，不扩展产品语义。

## 浏览器状态与数据归属

- 无客户端持久化数据：页面为只读静态展示，不读写 `localStorage` 或其他客户端存储。
- 无服务端状态、无会话、无用户身份。

## 实现入口

- 交付文件：`404.html`，位于项目根目录。
- 技术选型：原生 HTML5 + CSS3，不依赖构建工具或前端框架。选择纯静态 HTML 而非 React/Vite SPA 的理由：需求明确要求"纯静态 HTML""可直接由浏览器打开"，单页静态错误页无需组件化状态管理，纯 HTML 文件零依赖、零构建即可满足验收。

## 运行方式

- 直接在浏览器中打开 `404.html` 文件即可预览，无需开发服务器或构建步骤。
- 部署时将该文件放置于静态托管服务的 404 错误响应位置即可由托管平台自动返回。

## AC 覆盖

- AC-01：浏览器打开 `404.html` → 页面显示"404"标识与未找到提示 → 页面包含可点击的返回首页链接。验证方式为 runtime-render + visual-style，无特殊状态预置。
