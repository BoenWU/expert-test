# 采购申请单需求（kdtest_meta_cover）

> 工作项：wi-t1000362 · 文档：requirements.md · 修订：1 · 状态：需求基线（待开发）

## 1. 目标

在应用 kdtest_meta_cover 下新建一张采购申请单，供业务人员登记采购需求：录入需要采购的物品及数量等信息，保存单据并按苍穹标准单据流程流转。

## 3. 业务对象

| 对象 | 类型 | 状态 |
|---|---|---|
| 采购申请单 | 单据（单据头 + 单据体分录） | 新建（Create） |

采购申请单为苍穹标准业务单据：单据编号采用手工编码；生命周期为"保存 → 提交 → 审核"。用户未要求自动编号，本需求不承诺自动编号。

## 4. 主流程

1. 业务人员在 kdtest_meta_cover 中新建采购申请单，手工录入单据编号及采购需求信息（表头与分录）。
2. 保存单据；系统保存数据，单据可再次打开并回读已录入内容。
3. 提交单据，单据进入待审核状态。
4. 有审核权限的用户审核单据，单据进入已审核状态。

异常流程：

- 保存或提交时校验未通过（如必填信息缺失），系统给出错误提示，单据不流转。

## 6. 验收条件

- **AC-1（必测 · FR-1）**：给定 kdtest_meta_cover 中已部署采购申请单，当用户新建采购申请单并录入单据信息后执行保存，则保存成功，重新打开该单据可回读已录入信息。
- **AC-2（可选检查 · FR-2 平台标准规则）**：给定一张已保存的采购申请单，当依次执行提交、审核操作，则单据可完成提交进入待审核状态，审核后进入已审核状态且录入数据不变。

## 7. 假设与待决（专家建议，未经用户确认，不构成必测承诺）

- H-1 表头字段建议：单据编号（文本，必填，手工录入）、申请日期（日期，默认当天）、申请人（文本）、申请组织（文本）、备注（文本）。
- H-2 分录字段建议：物料编码（文本）、物料名称（文本）、数量（数量，大于 0）、计量单位（文本）、期望到货日期（日期）。
- H-1/H-2 的字段集、字段类型及是否改为基础资料引用（如物料、组织改为引用字段），可在开发前按用户意见调整；未确认前按上述假设执行，不阻塞本需求阶段。

## 8. 范围说明

- 本需求仅交付采购申请单一张单据及其录入、保存、提交、审核能力。
- 采购订单、采购入库等下游单据、BOTP 转换、多级审批流配置不在本次请求范围内（依请求范围推断，未经用户逐项确认，如需可另行提出）。
