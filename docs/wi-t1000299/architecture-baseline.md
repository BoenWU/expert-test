# 系统设计

## 1. 整体方案与设计基线

- 工作项：wi-t1000299
- 需求基线：docs/wi-t1000299/requirements.md（v1.0 初始基线，sha256:3327f5b64830447481f66eb7d7e9784365ffb8b3e28840fc859a9cdcd532e51e）
- 应用类型：simple-frontend（纯静态单页，无服务端）
- 日期：2026-10-19

### 架构结论

交付一个自包含的静态 HTML 页面（建议文件名 `404.html`，实现阶段可按托管平台约定调整文件名）。结构、文案直接写入 HTML，样式内联于页内 `<style>`，不引用任何外部 JS、CSS、字体或图片资源，不含脚本逻辑，无构建步骤。

### 技术承载依据

- NF-02、AC-03 与场景 J2 要求在无任何服务进程时以本地文件方式直接打开即完整渲染：`file://` 协议下浏览器会阻止外链 ES 模块与部分跨文件资源加载，因此采用单文件自包含形式，而非需要构建产物与 HTTP 服务器的 SPA 方案。
- FR-M1-3 要求"全部内容随页面文件本身交付"：内容、文案、样式的唯一载体即该 HTML 文件。
- 页面无状态、无数据、无复杂交互，引入框架或构建链无对应需求证据，按最小证据化设计省略。

### 运行方式

- 本地：浏览器直接打开 HTML 文件即可（`file://`），无需任何启动命令。
- 托管：文件可直接放置于任意静态站点根目录，或配置为服务器/托管平台的 404 错误页（如 `error_page 404 /404.html`）；页面内资源全部内联、链接使用相对目标，本地与托管两种方式行为一致。
- 无构建、无依赖安装、无启动/健康检查命令；不适用 `PORT`/`DB_PATH` 等参数。

### 浏览器本地状态与数据归属

页面无任何运行时状态：不使用 localStorage/sessionStorage、不发起网络请求、无脚本写入。全部展示内容的唯一 owner 为页面文件本身。

### 语言与编码

简体中文文案；文件 UTF-8 编码，根元素 `lang="zh-CN"`。

## 2. 领域责任、模块边界与接口摘要

单个页面承载全部职责，无内部模块拆分、无模块间接口、无外部系统调用。两个需求模块的技术落点：

| 需求模块 | 技术落点 | 数据/事实归属 |
| --- | --- | --- |
| M1 404 反馈展示 | HTML 语义结构：醒目"404"状态码标识 + 简体中文"页面未找到"主提示 + 一行辅助说明 | 页面文件本身（静态内容） |
| M2 返回入口 | 单个 `<a>`"返回首页"链接，样式与正文明确区分、可识别为可点击入口 | 链接目标为站点结构约定 |

### 页面/交互边界

- 打开即完成渲染，无加载过程。
- 唯一交互：点击"返回首页"触发浏览器原生导航。
- 无表单、无脚本交互、无动态内容。

### 返回链接目标约定（FR-M2-1）

- 托管场景：默认指向站点根路径 `/`。
- 纯本地文件场景：指向同目录 `index.html`。
- 实现阶段按实际站点结构确定默认值，但必须保证存在一个可用的返回入口。

### 调用方向（全系统仅此一条）

```text
访问者浏览器 → 404.html（自包含，零外部请求）→（点击返回入口）→ 站点根路径 / 或同目录 index.html
```

## 3. UI 基线

- 呈现形态：单屏垂直居中布局；层级为"404"大号状态码标识 → "页面未找到"中文主提示 → 一行辅助说明 → 返回首页入口。
- 视觉承载：全部样式内联于页内 `<style>`；不引用外部字体、图标库或图片，确保离线与 `file://` 场景零缺失。返回入口采用与正文明确区分的可点击样式（按钮式或强调链接样式，满足 FR-M2-2）。
- 目标设备：桌面现代浏览器（Chrome / Edge / Firefox 最新稳定版，NF-03）；不设计移动端/窄屏专用适配，不强制固定视口尺寸。
- 状态策略：页面本身即错误终态展示，无加载、空数据、权限等其他全局状态。
