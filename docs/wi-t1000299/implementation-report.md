## 1. 变更摘要与实现依据

新增一个自包含的 404 静态页面，浏览器直接打开即完整渲染"404 + 页面未找到 + 返回首页"闭环，全程零服务端依赖。实现依据为需求基线 FR-M1-1/2/3、FR-M2-1/2、NF-01/02/03 与架构基线确定的 simple-frontend 单文件自包含方案：结构、文案直接写入 HTML，样式内联于页内 `<style>`，不引用任何外部 JS/CSS/字体/图片，不含脚本逻辑，无构建步骤。

调用链（全系统仅此一条，与架构基线一致）：

```text
访问者浏览器 → public/404.html（自包含，零外部请求）→（点击“返回首页”）→ public/index.html
```

## 2. 实现范围（本次全部变更）

| 文件 | 角色 | 说明 |
| --- | --- | --- |
| `public/404.html` | 主交付物 | 404 页面：大号“404”状态码标识 → “页面未找到”主提示 → 一行辅助说明 → 按钮式“返回首页”链接；样式全部内联，单屏垂直居中，桌面现代浏览器优先 |
| `public/index.html` | 返回入口目标 | 站点极简首页（当前站点原本为空，无既有首页），与 404 页同一视觉基线 |

| `scripts/preview-server.mjs` | 开发辅助（可选） | 本地 HTTP 预览：提供 `public/` 内容，未匹配路径返回 `404.html`（HTTP 404）。仅为预览入口，站点交付不依赖它 |
| `README.md` | 文档 | 文件结构、本地直开方式、预览用法、静态托管/错误页部署说明、检查命令 |

## 3. 关键实现决策

1. **站点根取 `public/` 目录，文件名保持 `404.html`。** 本阶段源码写入范围不含仓库根级 `404.html`，`public/` 是通用静态站点根目录约定；部署时以 `public/` 目录内容作为站点根（或将服务器错误页指向 `/404.html`，见 README），与架构基线"文件可直接放置于任意静态站点根目录"一致。
2. **创建 `index.html` 作为返回入口目标。** FR-M2-1 规定纯本地文件场景返回入口指向同目录 `index.html` 且“必须保留一个可用的返回入口”；当前站点为空、不存在独立首页，故按需求允许的实现调整路径创建最小首页，保证 `file://` 直开与托管两种场景下“返回首页”均落到真实存在的页面，而非失效链接。
3. **返回链接使用相对目标 `href="index.html"`。** 架构基线不含脚本逻辑，无法按协议切换目标；相对链接在 `file://` 直开时解析为同目录首页、在托管部署时解析为站点根首页，两种场景行为一致，同时满足 FR-M2-1 的两个基线场景。
4. **零外部资源、零脚本。** 页面不引用任何外部 JS/CSS/字体/图片，无 `fetch`/存储/脚本逻辑，内容唯一载体即页面文件本身（FR-M1-3、NF-01）；`file://` 协议下外链资源受限，内联形式保证直开零缺失（NF-02、场景 J2）。
