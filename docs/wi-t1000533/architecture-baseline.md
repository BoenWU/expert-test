# 架构基线：404 静态网页

## 需求引用

- 需求基线：`docs/wi-t1000533/requirements.md`（sha256:0e98d63f5e00ef1b1a7492ae46654ebbcb0dd441a49cc4e95828ade9eed2334c）。
- 原始任务：实现一个 404 静态网页，不需要服务端（T1000533）。

## 应用形态与承载方式

- **交付形态**：单个静态 HTML 文件，全部样式与脚本（如有）内联在该文件中，不引用任何外部资源、数据接口或服务端渲染。
- **构建与运行边界**：无构建步骤、无开发服务器、无服务端进程。浏览器以 `file://` 协议直接打开即可完整渲染，与需求"无需 Web 服务器、后端服务或构建工具支持"一致。
- 因此不引入 React/Vite SPA 或任何前端构建工具链——需求已明确排除对构建工具的依赖。

## 页面与交互范围

- 页面核心内容（需求最小必需集）：
  - 醒目的 "404" 状态标识；
  - "页面未找到"提示文案。
- 允许的轻量增强（需求未规定事项，实现可自行决定，不扩展产品语义）：
  - 一个返回首页/上一页的静态链接；
  - 简单的视觉样式（配色、排版、居中布局）。
- 不含表单提交、路由跳转逻辑、数据读写或任何与用户的会话状态交互。

## 状态与数据归属

- 无浏览器状态、无持久化存储、无服务端数据：本页面为纯静态展示，每次打开行为完全一致。
- 不虚构服务/API、数据库、认证、后台任务、外部集成或同步层。

## 实现入口与运行方式

- 实现入口：单个 HTML 文件（`404.html`），由实现阶段在工作区源码范围内创建。
- 运行方式：浏览器直接打开该 HTML 文件即可渲染；页面用途为当用户访问不存在的页面或资源时展示 404 提示，无需启动任何服务端程序。

## 验证边界

- 唯一验收标准 AC-01（浏览器直接打开可正常渲染）为确定性静态渲染，页面内容固定，不涉及自动推进、随机结果、动画或异步事件，无需测试控制入口。
- 实现与验证阶段均以浏览器直接打开文件为执行路径。
