# 待办事项应用需求

## 需求来源
- 用户明确提出：新建一个简单应用，类型为待办事项。
- 推荐基线：为闭合最小可用闭环，待办事项需支持新增、列表查看与标记完成。
- 未规定事项：具体平台、技术实现、删除/编辑、优先级、提醒、多端同步。

## 目标
提供一个最小可用的待办事项应用，让用户能够记录待办、查看待办清单，并将已完成事项标记出来。

## 核心行为
1. 用户新增一条待办事项。
2. 待办事项以列表形式展示，用户可查看当前待办。
3. 用户可将某条待办事项标记为完成，完成后其状态可被识别。

## 验收标准

### AC-01：用户可完成待办事项的核心闭环
- 验收条件：用户能新增待办事项、在列表中查看它，并将其标记为完成。
- 入口类型：用户界面
- 验证动作：新建一条待办事项，在列表中找到它，并将其标记为完成。
- 预期结果：新建的待办事项出现在列表中；标记完成后，该事项的完成状态可见。
- 证据类型：interaction
