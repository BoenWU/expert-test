# 需求文档：502 静态网页

## 目标

提供一个 502 Bad Gateway 静态错误页面，用户在浏览器中直接打开即可看到标准的 502 错误提示，无需任何服务端支持。

## 用户明确提出的需求

- 实现一个 502 静态网页
- 不需要服务端

## 核心行为与规则

1. **页面内容**：页面展示「502 Bad Gateway」错误标题和简短说明文案，告知用户网关服务暂时不可用。
2. **纯静态**：页面为单一 HTML 文件（可内联 CSS），不依赖任何后端服务、构建工具或外部框架。
3. **直接打开**：用户通过浏览器以 `file://` 方式直接打开文件即可正常显示，无需启动本地服务器。
4. **页面自适应**：页面在常见桌面和移动浏览器宽度下均可正常阅读。

## 推荐基线

- 内联基础样式使页面居中、可读，风格简洁中性。此为最小可逆的视觉基线，不构成产品设计决定。

## 未规定事项

- 具体文案措辞、配色方案、品牌元素：用户未指定，不在本次基线中约束。
- 多语言支持：用户未要求，不纳入。
- 页面图标或动画效果：用户未要求，不纳入。

## 验收场景

### AC-01：浏览器直接打开页面可显示 502 错误内容
- 验收条件：用户在浏览器中直接打开静态 HTML 文件，页面显示「502 Bad Gateway」标题及说明文案。
- 入口类型：用户界面
- 验证动作：在浏览器中以本地文件方式打开该 HTML 文件。
- 预期结果：页面正常渲染，标题包含「502」，并展示网关错误相关说明文案；无需启动任何服务。
- 证据类型：runtime-render, visual-style
