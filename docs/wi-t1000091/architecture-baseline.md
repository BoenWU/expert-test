# 爱心静态网页 架构基线

## 设计依据

本基线以已批准的需求快照 `docs/wi-t1000091/requirements.md`（阶段契约校验哈希 `sha256:dde4ea894b1fe3714cdef93770d44749d0931b672982e37abf794ab3e2c7af08`）为唯一产品范围来源。设计只确定技术承载方式，不新增、缩减或重裁产品语义，也不在此文档重复验收场景。

## 分类结论

- 类型：`simple-frontend`（精简路线 `compact`）
- 判定依据：需求明确"不需要服务端"，页面内容随文件本地提供、不引用外部资源，且全部验收入口均为浏览器中的单个页面渲染；需求未出现账号权限、权威数据、后台任务、外部服务或跨用户共享等任何服务端能力诉求。动画、点击交互、音效、多尺寸适配被需求明确排除在基线之外。

## 页面与交互范围

- 单一页面、单一视图：页面主体为一个完整可辨识的爱心图案。
- 无多页面、无前端路由。
- 无表单、无用户输入、无业务操作按钮；页面加载完成即呈现结果，不需要额外点击或输入。
- 需求将动画与交互列为基线之外，因此本设计不实现动画、点击效果或音效，保持确定性静态渲染。

## 数据归属

- 无业务对象、无记录列表、无用户生成数据，因此不引入 `localStorage`、IndexedDB 或任何持久化层。
- 无用户身份与会话概念，页面结果与浏览器、设备、账号无关。

## 技术选型与实现入口

- 实现入口：项目根目录的 `index.html` 单文件页面。样式内联在 `<style>` 中，爱心主体以内联 `<svg>` 的路径数据直接绘制。
- 运行时依赖：零第三方库。不引入 React、UI 组件库、图标库或任何远程字体、图片、脚本、样式表。
- 构建工具：Vite 仅作为开发预览与生产构建工具（devDependency），不进入页面运行时。选择理由：需求要求"直接以本地文件方式打开即可看到爱心"，若采用 React 组件化方案，构建产物会依赖外部 module 脚本在 `file://` 下的跨源加载，反而削弱该验收条件的可靠性；页面本身无状态与交互，组件化没有收益。
- 因此相对团队"npm + React/Vite 静态 SPA"的默认基线，本应用收敛为"npm + Vite 构建的原生静态单页"，属于按实际依赖与验收条件调整，不改变纯前端数据边界。
- 构建配置要点：`base: './'`，构建输入为根 `index.html`，输出目录 `dist`；由于页面无外链脚本与样式，构建产物为单文件 `dist/index.html`，可直接以 `file://` 打开。
- 运行方式：
  - 开发预览：`npm run dev`（Vite 开发服务器）。
  - 生产构建：`npm run build`；构建产物预览：`npm run preview`。
  - 直接打开：根 `index.html` 与 `dist/index.html` 均可脱离任何服务器，以本地文件方式在浏览器中打开。

## UI 与视觉方向

- 团队默认的 Ant Design 管理工作台方案不适用：本应用不是工单或管理类工作台，没有侧栏、顶部上下文、筛选、表格或组织维度等内容表面，引入组件库只会带来无收益的依赖。
- 视觉方向：极简单页展示。深色渐变背景配高饱和红粉爱心，爱心水平垂直居中，与背景形成明确对比。
- 爱心形状：左右对称，上部两瓣圆弧饱满，下收为尖角；以 SVG 路径绘制，缩放在常见桌面窗口内保持形状清晰、完整可见、不被裁切。
- 不把 emoji 或 Unicode 符号当作图形或图标使用；爱心为矢量路径绘制。
- 需求未规定文案、配色与标题，这些属于实现侧常规取舍，但需满足"形状清晰""对比度足够""完整可见"这三项已声明的视觉约束。

## 无服务端与离线边界

- 页面加载过程不发起任何网络请求：无外部 `<link href>`、无外部 `<img src>`、无外部 `<script src>`、无 `@font-face` 远程地址、无 `fetch` 调用。
- 页面不含 ES module 脚本，因此以 `file://` 打开时不存在跨源模块加载被阻断的风险。
- 不使用 Service Worker、不使用需要联网初始化的第三方 SDK。
- 结论：在未启动任何后端服务且无网络连接的条件下，页面样式与爱心图案均能正常呈现，不出现空白或错乱。

## 部署基线

- 已运行前端部署初始化器，生成工作区基线文件 `deploy/Dockerfile` 与根目录 `.dockerignore`，作为可选的静态托管方式（以静态文件服务器托管构建产物），不影响上述离线直接打开结论。
- 部署文件属于工作区基线，不作为本阶段设计产物；阶段完成时由运行时执行前端部署基线校验。
- 构建命令、输出目录如需与静态托管保持一致，实现阶段以 `npm run build` 产出 `dist` 为准。

## 自动化验证可行性

- 本应用不涉及随机结果、动画推进、定时任务、长状态路径或外部异步事件，页面渲染完全确定性：相同文件在两次加载中呈现结果一致。
- 因此无需预置状态、固定随机结果、手动推进或测试专用控制入口；验证直接以打开页面后观察渲染结果为准。
- 证据口径区分：页面可打开且爱心可见属渲染结果证据；"无外部资源请求"属网络请求观察证据；两者需分别取得。

## 明确不做的事

- 不生成 `technical-contract.md`、`workspace-bootstrap.json`、ADR 或实现计划。
- 不引入服务端 API、数据库、认证鉴权、后台任务、外部集成或数据同步层。
- 不承诺移动端与多尺寸适配，不实现需求未要求的交互与增强能力。
- 不修改已批准需求文件；若后续需要改变上述技术选型、数据边界或离线约束，走设计变更流程。
